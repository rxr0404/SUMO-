# 三、交通调控实验报告：匝道信号灯绿灯时间对交通运行的影响

## 1. 实验设计

**实验平台**：SUMO 1.27.1 + TUD-SUMO 3.3.2（Python 通过 TraCI 与 SUMO 交互）

**实验场景**：复用第二部分的论文复现场景——高速公路 2 车道主线 + 1 车道匝道汇入（汇入点下游拓宽为 3 车道），交通需求 2000 s：主线 1000→1500→1000 veh/h（400–1600 s 为高峰），匝道恒定 500 veh/h。

**调控参数**：匝道信号灯 RM 的**绿灯时间**（作业给定示例之一）。

**对照方案**（单一变量：其余需求、路网、步长 0.5s、随机种子 42 全部相同）：

| 方案 | 信号配时（绿/黄/红） | 周期 | 放行能力（估算） | 与匝道需求 500 veh/h 的关系 |
|---|---|---|---|---|
| 方案0（调整前/基线） | 常绿 | — | 不受限 | — |
| 方案A（调整后） | 2s / 1s / 7s | 10s | ≈ 360 veh/h | **低于需求** → 排队累积 |
| 方案B（调整后） | 6s / 1s / 3s | 10s | ≈ 900 veh/h | 高于需求 → 基本无排队 |

> 放行能力估算：一个周期内从静止起步约能放行 `max(1, (G−2s)/2s + 1)` 辆车（起步损失约 2s，饱和车头时距约 2s），除以周期即得小时流率。

**实现方式**：`run_experiment.py` 用 TUD-SUMO 依次启动三次仿真，每次通过 TraCI 的
`set_phases({"RM": {...}})` **在运行时把信号方案写入 SUMO**（这就是"Python 与 SUMO 交互"的动作本身），
跑完自动提取行程、排队、全网延误指标并绘图。

**运行方法**（结果均由本脚本实际运行产生）：

```bat
cd /d D:\智能交通\交通调控实验
python run_experiment.py
```

若要在 GUI 中直观观看某一方案（可另存运行截图）：

```bat
sumo-gui -c scenario\sim.sumocfg -a plans\planA_short_green.add.xml --start --delay 25
```

（方案A 可以直接看到匝道车辆排成长队的画面；把 planA 换成 plan0/planB 可对比。）

## 2. 实验结果

### 2.1 指标对比表（outputs/对比汇总.csv）

| 指标 | 方案0 常绿（基线） | 方案A 短绿灯 | 方案B 长绿灯 |
|---|---|---|---|
| 完成行程车辆数（辆） | 968 | **894** | 968 |
| 仿真结束时未完成车辆数（辆） | 33 | **76** | 33 |
| 其中匝道车辆完成数（辆） | 266 | **192** | 266 |
| 匝道车辆平均行程时间（s） | 168.3 | **706.8** | 173.5 |
| 主线车辆平均行程时间（s） | 159.0 | 158.8 | 158.9 |
| 全网总等待时间（s） | 0 | **881** | 40 |
| 全网总延误（s） | 3992 | **69570** | 4673 |

### 2.2 对比图（outputs/对比图_绿灯时间实验.png，四联图）

- **(a) 匝道排队规模**：方案A（短绿灯）的匝道在车数从约 300s 起持续线性上升，约 1200s 后达到
  50 辆并饱和（排队回溢到匝道入口，新车无法进入路网）；方案0/方案B 全程仅 0~7 辆，正常波动。
- **(b) 主线汇入段速度**：三种方案基本重合（约 110~120 km/h）——本场景主线总需求
  （峰值 2000 veh/h）低于 3 车道通行能力，且方案A 的排队被限制在匝道上，未波及主线。
- **(c) 匝道车辆平均行程时间**：方案A 达 706.8 s，是基线（168.3 s）的 **4.2 倍**；方案B（173.5 s）
  与基线几乎一致，仅略增（红绿灯本身引起的少量停等）。
- **(d) 完成车辆数**：方案A 只有 894 辆完成行程（55 辆匝道车到仿真结束仍被堵在匝道/未插入）；
  方案0/方案B 均为 968 辆。

### 2.3 结论

1. **绿灯时间决定了匝道的放行能力，必须与到达需求匹配。** 方案A 的放行能力（≈360 veh/h）
   低于匝道需求（500 veh/h），缺口 140 veh/h 使排队以近似恒定速率累积（图a 的直线段），
   最终回溢到匝道入口，阻断新车进入路网——匝道车辆平均行程时间膨胀 4.2 倍，全网总延误
   从 3992 s 恶化到 69570 s（约 17 倍）。
2. **绿灯时间并不是越长越好，但"够用"之后收益边际递减。** 方案B（≈900 veh/h）相比常绿基线，
   各项指标几乎不变、仅略有增加（红绿灯停等本身引入少量延误）——当放行能力高于需求时，
   控制不会带来额外收益，反而有轻微代价。
3. **信号控制的影响是"有针对性的"**：三种方案下主线车辆平均行程时间几乎不变（159 s 上下），
   说明在本场景（主线未饱和）中，匝道信号灯只把代价施加在匝道车流上；
   若主线饱和（如高峰延续更久），压缩匝道绿灯才会体现"用匝道排队换主线畅通"的收益——
   这正是 ALINEA 等自适应控制（第二部分 Test D）要解决的问题：按下游占用率实时调节绿灯放行率。
